### 🔭 Project architectures

**AWS CI/CD Platform: blue/green with automatic rollback**

```mermaid
flowchart LR
    A[Commit] --> B[CodePipeline]
    B --> C[CodeBuild<br/>test + build once]
    C --> D[(ECR<br/>SHA-tagged image)]
    D --> E[ECS Fargate: Dev]
    E --> F{Manual SNS<br/>approval}
    F --> G[CodeDeploy canary<br/>10% for 5 min]
    G -->|5xx alarm clear| H[100% traffic]
    G -->|5xx alarm fires| I[Automatic rollback]
```

**LiveQuiz: GitOps flow**

```mermaid
flowchart LR
    A[App repo] --> B[GitHub Actions<br/>test + build]
    B --> C[(GHCR<br/>SHA tag)]
    B --> D[Deploy repo<br/>new tag committed]
    D --> E[ArgoCD]
    E --> F[k3s on EC2<br/>Terraform-built]
    D -. git revert .-> E
```

<details>
<summary><b>☁️ AWS CI/CD Platform: details</b></summary>
<br>

- Each commit is **tested and built once**, tagged with its SHA, deployed to dev, then promoted to prod behind a **manual SNS approval gate**
- **Blue/green canary deploys** with CodeDeploy (10% traffic for 5 minutes) and a CloudWatch 5xx alarm
- Demonstrated **automatic rollback** using a simulated fault that passed health checks but failed real requests
- **Least-privilege IAM** per service and **immutable ECR tags**, so every running version maps to exactly one commit
- Per-environment CloudWatch dashboards plus teardown and billing-check scripts (about $0.15/hr with both environments up)

</details>

<details>
<summary><b>🔁 LiveQuiz: details</b></summary>
<br>

- **GitHub Actions** tests the app, pushes a **SHA-tagged image to GHCR**, then commits the new tag to a separate deploy repo
- **ArgoCD + self-written Helm chart**: dev auto-syncs with self-heal; prod changes only via reviewed PR plus manual Sync
- **Terraform** provisions EC2 + k3s (single-IP security group, IMDSv2, encrypted disk); the full environment **rebuilds from code in about 10 minutes**

</details>

<details>
<summary><b>🚦 DeployGate: details</b></summary>
<br>

- Multi-stage Docker build producing a minimal **non-root** image
- Declarative **Jenkins pipeline as code**: build, 37 unit tests, SonarCloud analysis, image build/tag on every commit
- Deployed to **k3s on EC2** with Deployments, Services, ConfigMaps, Secrets, PVCs and in-cluster PostgreSQL
- **Prometheus + Grafana** monitoring (7 healthy scrape targets verified via PromQL)
- Diagnosed an I/O bottleneck (84.9% I/O wait) and an undersized EBS volume using `top`, `free` and CloudWatch; provisioning automated with **Ansible**

</details>

## 🧭 How I Work

| Principle | What it looks like in my projects |
|---|---|
| 🔁 **Build once, promote everywhere** | One SHA-tagged image moves from dev to prod, so what I tested is what ships |
| ⏪ **Rollback should be boring** | `git revert` in GitOps, automatic canary rollback on AWS |
| 🔒 **Least privilege by default** | Per-service IAM, IMDSv2, single-IP security groups, encrypted disks |
| 🏗️ **Everything as code** | Terraform, Helm and pipelines in Git, with environments rebuilt on demand |
| 💸 **Cost awareness** | Teardown and billing-check scripts keep lab environments near zero |
| 🔎 **Find the root cause** | RCA habits from production support, not just clearing the alert |
